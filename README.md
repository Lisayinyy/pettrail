# 宠迹 PetTrail

[在线体验](https://lisayinyy.github.io/pettrail/)

养宠成长记录与社区的可交互产品原型：一个 `index.html`，没有后端、没有构建步骤，数据保存在当前浏览器的 `localStorage`，页面预置了两只宠物的演示数据。

这是「爪印日记」（[pawprint](https://github.com/Lisayinyy/pawprint)）之前的概念验证，用来确定信息架构和核心流程；真实账号、云端同步和家庭共管在 pawprint 里实现。

## 原型里能做什么

- **首页**：宠物档案、健康管理分、到期提醒、一键记录。
- **健康**：体重曲线（含品种成年参考区间）、疫苗、驱虫、就诊用药，可导出文本版健康档案。
- **时间线**：所有记录按月汇成成长时间线，自动补生日和相伴天数里程碑，可生成成长报告并分享到社区。
- **宠友**：按城市、距离、品种、年龄给预置宠友打匹配分，含同城活动报名和模拟对话。
- **社区**：话题筛选、发帖、点赞、评论，日常可同步进时间线。

宠友、活动和自动回复是写在页面里的演示数据，匹配分是页面内的规则打分，没有真实用户或模型调用。

## 本地运行

```bash
python3 -m http.server 8000
# 打开 http://localhost:8000/
```

也可以直接双击 `index.html`。桌面端左侧说明栏里的「重置演示数据」会清掉本地改动。

## 结构

`index.html` 自上而下：样式 → 页面骨架 → 工具函数与日期处理 → 演示数据 `seed()` 与本地存储 → 提醒和健康分规则 → 五个标签页的视图 → 表单与弹层。

规则都在页面里，可以直接读：

- **提醒**：疫苗取最近一条记录的「下次」日期；驱虫按体内、体外各取最近一条；称重固定为上次称重后 30 天。
- **健康分**：从 100 分起，每个逾期提醒扣 8 分、每逾期满一周再扣 3 分（单项最多 25 分）；成年后体重超出品种参考区间扣 10 分；相邻两次称重变化超过 10% 扣 8 分；最低 30 分。
- **日期**：所有日期都是访客本地时区的日历日 `YYYY-MM-DD`，加减天数用本地日历计算，不经过 UTC。

## 测试

```bash
node --test        # 需要 Node 22 或更新版本，不用安装依赖
```

页面没有拆文件：`tests/page.mjs` 把 `index.html` 里的脚本原样放进一个 V8 上下文，配上固定时钟、内存版 `localStorage` 和最小的 `document`，测试直接调用页面自己的函数。共 23 个用例，覆盖三件事：

| 检查 | 做法 | 结果 |
|---|---|---|
| 日期计算不随时区跑偏 | 2026–2027 年的每一天，在 7 个时区（上海、洛杉矶、UTC+14、UTC−12，以及在午夜切换夏令时的圣地亚哥、开罗和半小时夏令时的豪勋爵岛）各算一遍加天数、差天数和显示 | 现在 7 个时区 730 天全部正确；修日期问题之前的版本（提交 `6447ca0`）在洛杉矶、UTC−12、圣地亚哥这三个西半球时区 730 天全部差一天 |
| 提醒与健康分规则 | 固定「今天」，按上面的规则逐条断言 | 通过 |
| 本地存档损坏时页面仍能打开 | 11 种损坏的存档（不是 JSON、缺字段、条目为 `null`、记录没有日期等），五个标签页逐个渲染 | 本轮之前有 6 种会让页面白屏或时间线打不开；现在丢掉坏条目、保留其余数据，全部能打开 |

## 已知限制

- 这是原型：没有账号，数据只在当前浏览器，换设备或清缓存就没有了。
- 2 月 29 日出生的宠物，平年的生日里程碑显示在 3 月 1 日。
- 测试覆盖日期、规则和存档恢复；表单、弹层和样式没有自动化测试，是在浏览器里手动检查的。

## 参考

- 多时区重复跑同一组日期测试的做法来自 [date-fns](https://github.com/date-fns/date-fns) 的 `pkgs/core/scripts/test/tz.sh`（每个用例用 `env TZ=…` 单独跑，专门挑在午夜切换夏令时的时区）。这里改成在同一个进程里切换 `TZ`，并先断言时区偏移确实生效。
